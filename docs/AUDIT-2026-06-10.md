## Findings and resolutions

### L-1 Per-stock volatility was immutable after `addStock`

`SigmaVault` had no way to update a stock's annualized volatility, a core VaR
input, without redeploying. **Fixed**: `setVol(stock, volWad)` added with the
same bounds as `addStock` (`0 < vol <= 5e18`), owner-only, with a
`VolatilityUpdated` event and three new tests. Stock delisting remains
intentionally unsupported: removing a stock while users hold it as collateral
would zero their portfolio value and corrupt liquidation incentives.

### L-2 Oracle pause freezes liquidations and indebted withdrawals

When the adapter is paused, `getPrice` reverts, so `health()` reverts, so
`liquidate` and `withdraw` (for indebted users) revert too. Pausing during a
price emergency also disables the protocol's own defense mechanism.
**Resolution**: documented as a known prototype limit in the README. The
production path is per-asset circuit breakers with a grace-period unwind,
which is out of scope for the testnet prototype.

### L-3 Oracle deviation gate can deadlock after a reporter outage

If price moves more than `maxDeviationBps` between successful publishes,
later updates revert with `ExcessiveDeviation`. Recovery: the owner raises
`maxDeviationBps` (hard-capped at 50%), the reporter publishes staged steps
toward the market price with strictly increasing observation timestamps, and
the owner restores the limit. A move beyond 50% between publishes cannot be
recovered because the owner deliberately cannot write prices directly.
**Resolution**: recovery procedure documented in the README known limits.

### L-4 Optimistic chain id after a wallet network switch

`wallet.tsx` set the React chain id unconditionally after
`wallet_switchEthereumChain` resolved, and `sendTransaction` validated
against that state. A wallet that resolves the request without actually
switching could have submitted a transaction on the wrong chain. **Fixed**:
the chain id is read back from the provider after the switch, and
`sendTransaction` now performs an authoritative `eth_chainId` check against
the provider immediately before submitting.

### Informational, fixed

- Guardian repayment now targets 2% past the policy minimum health factor so
  a marginal price move does not re-trigger it on the next scheduled run.
- The policy form in the operator panel resyncs only when the on-chain
  policy actually changes, so a background refresh after an unrelated action
  no longer clobbers values the user is editing.
- `web/lib/contracts.ts` strategist history now includes all three legacy
  Strategists, so the decision log renders receipts from every era.
- The unused `indexOf` mapping write was removed from `SigmaVault`.
- `parseAddress` in `wallet.tsx` no longer throws on malformed provider
  events.
- `SeedDemo` now grants the Strategist a bounded 150 USDC repayment
  allowance instead of an unlimited approval, matching the web flow.
- The Stylus core documents its saturating overflow semantics (the Solidity
  reference core reverts instead); Vault-validated inputs cannot reach those
  ranges.

### Informational, accepted as designed

- A repay through the Strategist restarts the cooldown window. Deleveraging
  is never blocked, but it postpones the next risk-increasing action. Now
  stated explicitly in a code comment.
- A user-designated Vault executor can `borrowFor` the user up to the health
  limit (proceeds always go to the user). The only executor the product ever
  configures is the Strategist, which enforces the user's policy.
- The seed repayment allowance is sized at setup; if the user later borrows
  directly above the policy cap, guardian repayment capacity is bounded by
  the allowance and degrades gracefully.
